# Contributing to Zenith

Thank you for your interest in contributing to Zenith! Zenith is a modern domain-specific language designed to eliminate Spring Boot boilerplate while keeping enterprise Java reliable, clean, and production-grade.

Whether you are fixing a compiler bug, improving syntax diagnostics in the VS Code extension, enhancing the Zenith Studio visual architecture IDE, or expanding documentation, your contributions are welcome.

## Development Setup

### Prerequisites

- **Java Development Kit (JDK) 17 or higher** (Eclipse Temurin, OpenJDK, or GraalVM). Verify with `java -version`.
- **Apache Maven 3.9+**. Verify with `mvn -version`.
- **Node.js 18+ and npm** (Required only for the Zenith Studio desktop packaging and VS Code extension). Verify with `node -v` and `npm -v`.
- **Visual Studio Code** (Recommended IDE for extension development).
- **Git**.

### Getting Started

1. **Fork and Clone the Repository**:
   ```bash
   git clone https://github.com/<your-username>/zenith-lang.git
   cd zenith-lang
   ```

2. **Build the Zenith Compiler and Fat JAR**:
   We provide automated build scripts in the project root:
   - **Windows**:
     ```cmd
     .\build-cli.bat
     ```
   - **Linux / macOS**:
     ```bash
     mvn clean package
     ```
   This compiles all Java source files under `src/main/java` and updates the standalone executable JAR in `bin\zenith.jar`.

3. **Verify the CLI**:
   ```cmd
   .\bin\zenith.bat inspect zenith-exemples\nexus-commerce\schema.zen
   ```

4. **Launch Zenith Studio for Live Testing**:
   ```cmd
   .\bin\zenith.bat studio zenith-exemples\nexus-commerce\schema.zen
   ```
   Open `http://localhost:3000` to verify live editing, Monaco syntax diagnostics, ERD rendering, and ZIP export.

## Codebase Architecture

Zenith is organized into modular layers:

```
src/main/java/dev/zenith/
├── lexer/             # Tokenization (ZenithLexer, TokenType, Token)
├── parser/            # Recursive-descent AST parser (ZenithParser, ParseException)
├── ast/               # Abstract Syntax Tree nodes (ZenithFile, ModelNode, EndpointNode...)
├── analyzer/          # Semantic validation, foreign key checks, duplicate detection
├── generator/         # Code transpilation to Spring Boot 3 + Java 17
│   ├── EntityGenerator.java       # JPA @Entity models with column constraints
│   ├── DtoGenerator.java          # Request / Response Java records
│   ├── RepositoryGenerator.java   # Spring Data JPA repositories with query derivations
│   ├── ServiceGenerator.java      # Service interfaces and @Transactional implementations
│   ├── ControllerGenerator.java   # Spring MVC @RestControllers with Swagger annotations
│   ├── SecurityGenerator.java     # Spring Security 6, JWT, filters, and @PreAuthorize RBAC
│   ├── FlywayGenerator.java       # Versioned V1__initial_schema.sql DDL migrations
│   ├── StorageGenerator.java      # MinIO and AWS S3 multi-part object storage
│   ├── JobGenerator.java          # @Scheduled background tasks and cron workers
│   ├── TestGenerator.java         # Automated JUnit 5 + MockMvc integration test suites
│   ├── DockerGenerator.java       # Multi-stage Dockerfile and docker-compose.yml
│   └── SdkGenerator.java          # TypeScript HTTP client and React Query hooks
├── studio/            # Embedded lightweight HTTP / WebSocket server for the Studio IDE
└── cli/               # Command-line interface driver (ZenithCli)
```

Other directories:
- `src/main/resources/studio/`: The self-contained Zenith Studio web frontend (HTML5, Vanilla CSS, Monaco Editor, Canvas ERD, API Tester).
- `zenith-vscode/`: The official VS Code syntax highlighting extension and TextMate grammar (`syntaxes/zenith.tmLanguage.json`).
- `desktop/`: Native Electron wrapper configuration and NSIS installer scripts (`build-desktop.bat`).
- `zenith-exemples/`: Reference modular domain projects (e.g., `nexus-commerce`).

## Development Guidelines

### Java Code Standards

1. **Target Java 17**: Use modern Java features appropriately: `record` classes for immutable data, `switch` pattern matching, `var` where type inference enhances readability, and `Optional` where return values may be absent.
2. **Minimal Dependencies**: The Zenith compiler runtime has zero external heavy framework dependencies. Keep the compiler fast, self-contained, and lightweight.
3. **Generated Code Quality**: When modifying code generators in `dev.zenith.generator`, always ensure the output Java code is:
   - Idiomatic Spring Boot 3.
   - Clean, formatted, and easily readable by human developers.
   - Free from deprecated APIs, warnings, or raw types.

### Testing Changes

1. **Run Unit and Integration Tests**:
   ```bash
   mvn test
   ```
2. **End-to-End Validation**:
   Compile one of the complex reference schemas to verify generated project validity:
   ```cmd
   .\bin\zenith.bat build zenith-exemples\nexus-commerce\schema.zen -o target\test-run
   cd target\test-run
   mvn test
   ```
   Ensure `mvn test` passes cleanly in the generated Spring Boot service.

3. **VS Code Extension Testing**:
   If modifying syntax highlighting or snippets in `zenith-vscode/`:
   ```cmd
   .\update-extension.bat
   ```
   In VS Code, press `Ctrl + Shift + P` -> `Developer: Reload Window` and verify `.zen` file highlighting.

## Pull Request Workflow

1. **Create a Feature Branch**:
   ```bash
   git checkout -b feat/your-feature-name
   # or
   git checkout -b fix/your-bug-description
   ```

2. **Make Focused Commits**:
   Follow [Conventional Commits](https://www.conventionalcommits.org/):
   - `feat: add support for @unique constraint on composite keys`
   - `fix: resolve null pointer when reciprocal relation is omitted`
   - `docs: improve CLI watch command documentation`
   - `perf: optimize topological sort in ERD canvas`
   - `test: add unit test for nested DTO generation`

3. **Self-Review Checklist Before Opening a PR**:
   - [ ] `mvn clean test` passes with zero failures.
   - [ ] The standalone JAR compiles cleanly via `.\build-cli.bat`.
   - [ ] No unwanted debug statements (`System.out.println` or `console.log`) remain in production paths.
   - [ ] New features or syntax changes include corresponding test cases or reference examples.
   - [ ] Documentation (`README.md`, `ROADMAP.md`, or Studio reference) is updated if command flags or syntax changed.

4. **Submit Your Pull Request**:
   - Push your branch to your fork: `git push origin feat/your-feature-name`.
   - Open a pull request against the `master` branch of `ouerghi0x/zenith-lang`.
   - Provide a clear, detailed description of the problem solved, architectural choices, and verification steps.

## Reporting Issues & Feature Requests

- **Bug Reports**: Open an issue detailing your OS, Java version, the exact `.zen` schema snippet that triggered the issue, and the full stack trace or CLI output.
- **Feature Proposals**: Before undertaking large syntax or architectural changes, please open an issue with the `[RFC]` or `[Proposal]` tag to align on design and syntax grammar.
