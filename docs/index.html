Zenith DSL Documentation

Zenith is a domain-specific language designed to eliminate the 9-file boilerplate ceremony of Java and Spring Boot. Declare your models, validation constraints, relations, security policies, background workers, and REST endpoints in clean .zen files and compile directly into production-ready Spring Boot 3 applications in milliseconds.

Overview & Philosophy

In traditional Spring Boot development, exposing a single validated, secured CRUD resource requires creating 7 to 9 separate files: Entity.java, CreateRequest.java, UpdateRequest.java, Response.java, Repository.java, Mapper.java, Service.java, ServiceImpl.java, and Controller.java (~350 lines of repetitive ceremony).

Zenith unifies this into a single strongly-typed AST. When you modify your schema, all downstream artifacts—JPA entities, Flyway migrations, Spring Security filters, MockMvc test suites, and frontend TypeScript clients—update in complete lockstep.

Installation & CLI Commands

The Zenith compiler is distributed as a single standalone executable JAR requiring Java 17+. Install via Scoop on Windows, download the standalone binary, or install the VS Code language extension.

Command Arguments Description
zenith build <file.zen> [-o <output-dir>] Transpiles the schema into a complete Spring Boot 3 Maven project.
zenith watch <file.zen> [-o <output-dir>] Starts hot-reload daemon; regenerates application code on file save (< 150ms).
zenith validate <file.zen> Performs lexing, AST parsing, and semantic analysis; reports exact errors.
zenith inspect <file.zen> Prints an architectural summary of detected models, relations, DTOs, and endpoints.
zenith studio <file.zen> [--desktop] [--port 3000] Launches Zenith Studio — available both as a local web IDE and native standalone desktop app.
zenith init [name] Scaffolds a clean starter schema.zen file in the current directory.

1. Application Configuration (config)

The config { ... } block declares global application properties, database engines, security configurations, and infrastructure integrations.

Property Type Default Description
app String "ZenithApplication" Spring Boot application name and main class prefix.
package String "com.example.app" Root Java package directory for all generated classes.
basePath String "/api" Common root path prefix prepended to all REST endpoints.
port Integer 8080 HTTP server port (server.port).
database postgres | h2 postgres Target SQL dialect and driver configuration.
auth jwt | none none Activates Spring Security 6, JJWT token filter, and auth endpoints.
jwtSecret String Auto default Custom HMAC-SHA256 secret (min 32 chars). Supports ${JWT_SECRET:...} env var override.
jwtExpiration Long 86400000 Token TTL in milliseconds (default: 24h). Supports ${JWT_EXPIRATION_MS:...} env var override.
storage minio | s3 minio Object storage provider for @file and @image uploads.
flyway Boolean true Generates idempotent V1__initial_schema.sql migration scripts.
swagger Boolean true Enables SpringDoc OpenAPI 3 UI on /swagger-ui.html.
config.zen 
config {
    app: "NexusCommerce"
    package: "com.nexus.commerce"
    basePath: "/api/v1"
    port: 8080
    database: postgres
    auth: jwt
    jwtSecret: "404E635266556A586E3272357538782F413F4428472B4B6250645367566B5970"
    jwtExpiration: 86400000
    storage: minio
    flyway: true
    swagger: true
}

2. Data Types & Nullability

Zenith primitives map automatically to SQL database columns, Java JPA field types, and TypeScript client interfaces. Fields are non-null by default; append ? to mark a field as optional. Assign default values using = value.

Zenith Type Java 17 Type PostgreSQL SQL Type TypeScript Type
String java.lang.String VARCHAR(255) string
Text / @text java.lang.String TEXT string
Int / Integer java.lang.Integer INTEGER number
Long java.lang.Long BIGINT number
Decimal java.math.BigDecimal NUMERIC(p,s) number
Boolean java.lang.Boolean BOOLEAN boolean
UUID java.util.UUID UUID string
Date java.time.LocalDate DATE string
DateTime java.time.LocalDateTime TIMESTAMP string
types_example.zen 
model CustomerProfile {
    id: UUID @id @auto
    fullName: String(min = 2, max = 100)
    bio: String? @text                    // Optional unbounded text
    rewardPoints: Int = 0                  // Defaults to 0
    balance: Decimal(precision = 10, scale = 2) @positive
    isVerified: Boolean = false
    birthDate: Date?
    lastLogin: DateTime?
}

3. Field Decorators & Validation Rules

Decorators attach database primary keys, validation rules, security behaviors, and media handlers directly to attributes.

Decorator Arguments Behavior & Emitted Code
@id — Marks field as table Primary Key (@Id in JPA).
@auto — Automated identity generation (GenerationType.IDENTITY or UUID random).
@unique — Adds unique database constraint and derived query findBy[Field].
@email — Enforces valid email format with Jakarta @Email.
@password — Hashes value with BCrypt; strips field from response DTO records.
@min(n) Number Validates minimum integer or string length constraint.
@max(n) Number Validates maximum integer or string length constraint.
@positive — Ensures numeric attribute is strictly greater than zero (@Positive).
@autoNow — Sets creation timestamp on @PrePersist.
@autoUpdate — Updates modification timestamp on @PreUpdate.
@role — Designates enum as user role authority for Spring Security.
@file path, maxSize Attaches cloud document upload endpoint (MinIO / S3).
@image path, types, maxSize Validates image MIME type and attaches cloud media upload endpoint.

4. Enums & Security Roles

Enums define finite states or access control roles. Decorating an enum with @role integrates it with Spring Security's GrantedAuthority hierarchy.

auth_enums.zen 
enum UserRole {
    ADMIN,
    STAFF,
    CUSTOMER
}

enum OrderStatus {
    PENDING,
    PAID,
    PROCESSING,
    SHIPPED,
    DELIVERED,
    CANCELLED
}

model UserEntity {
    id: UUID @id @auto
    email: String @email @unique
    password: String @password
    role: UserRole = CUSTOMER @role
    isActive: Boolean = true
}

5. Entity Relationships

Relationships are declared cleanly inside the relations { ... } block using @relation. Zenith generates foreign key columns, join tables, bidirectional links, and Jackson JSON serialization shields to prevent infinite recursion.

relations_example.zen 
model Category {
    id: Long @id @auto
    name: String @unique

    relations {
        products: List<Product> @relation(oneToMany, mappedBy = "category")
    }
}

model Product {
    id: Long @id @auto
    title: String
    price: Decimal

    relations {
        category: Category @relation(manyToOne)
        orderItems: List<OrderItem> @relation(oneToMany, mappedBy = "product")
    }
}

model Order {
    id: UUID @id @auto
    orderNumber: String @unique

    relations {
        customer: UserEntity @relation(manyToOne)
        items: List<OrderItem> @relation(oneToMany, mappedBy = "order")
    }
}

model OrderItem {
    id: Long @id @auto
    quantity: Int @min(1)
    unitPrice: Decimal

    relations {
        order: Order @relation(manyToOne)
        product: Product @relation(manyToOne)
    }
}

6. Standard CRUD Endpoints

The crud { ... } block declares standard REST endpoints: GET / (list with pagination/filter/search), GET /{id}, POST / (create), PUT /{id} (update), and DELETE /{id}.

crud_endpoints.zen 
model Product {
    id: Long @id @auto
    title: String
    sku: String @unique
    status: ProductStatus
    price: Decimal

    endpoints {
        crud {
            paginate: true                      // PageResponse<T> with ?page=0&size=20
            search: [title, sku]               // Case-insensitive ?search= query
            filter: [status]                   // Exact match query ?status=ACTIVE
            sort: [price, createdAt]           // Sorting ?sort=price,desc
            auth: true                         // Requires valid JWT token
            roles: {
                create: [ADMIN, STAFF],       // Emits @PreAuthorize("hasAnyRole('ADMIN','STAFF')")
                delete: [ADMIN],              // Emits @PreAuthorize("hasRole('ADMIN')")
                list: ["public"]              // Anonymous public access allowed
            }
        }
    }
}

7. Custom Routes & Request Bodies

Declare custom domain routes (get, post, put, delete) with path variables and decoupled DTO request bodies.

⚠️ Architectural Rule — Model DTOs Always End with Response or Request (Never Return Raw Entities):
For every model <ModelName>, Zenith auto-generates <ModelName>Response, Create<ModelName>Request, and Update<ModelName>Request. You cannot return a raw JPA entity as a REST API response (e.g., -> Order is rejected at compile time in Zenith Studio). Always return -> <ModelName>Response, -> List<<ModelName>Response>, a custom dto, or -> Void.
custom_routes.zen 
dto CheckoutItemRequest {
    productId: Long
    quantity: Int
}

dto CheckoutRequest {
    shippingAddress: String
    notes: String?
    items: List<CheckoutItemRequest>
}

model Order {
    id: UUID @id @auto
    status: OrderStatus = PENDING

    endpoints {
        // Custom POST endpoint accepting typed body and returning summary DTO
        post "/checkout" (body: CheckoutRequest) -> OrderSummaryResponse {
            auth: true
            action: {
                // Execute domain mutation logic
            }
        }

        // Route with path variable
        post "/{id}/cancel" -> Void {
            auth: true
            guard: status == OrderStatus.PENDING, "Only pending orders can be cancelled"
            action: {
                status = OrderStatus.CANCELLED
            }
        }
    }
}

8. Domain Actions & Guards

The action: { ... } block handles multi-entity mutations, automated audit logging, customer notifications, and conditional guards directly in your schema.

actions_example.zen 
post "/{id}/pay" -> OrderSummaryResponse {
    auth: true

    // 1. Guard check: fails with 400 Bad Request if false
    guard: status == OrderStatus.PENDING, "Only pending orders can be marked as paid"

    action: {
        // 2. State mutation on primary entity
        status = OrderStatus.PAID

        // 3. Instantiate secondary audit log entity
        create AuditLog {
            action = "ORDER_PAYMENT_PROCESSED",
            details = "Order " + entity.orderNumber + " marked PAID by " + currentUser.email
        }

        // 4. Dispatch notification to customer
        notify(entity.customer.email, "Your payment for order " + entity.orderNumber + " succeeded!")

        // 5. Return explicit DTO
        return OrderSummaryResponse {
            orderNumber = entity.orderNumber,
            totalAmount = entity.totalAmount,
            status = entity.status,
            paidAt = now()
        }
    }
}

9. DTOs & Custom Return Types

Define decoupled Java 17 records and TypeScript interfaces using dto Name { ... }. Note that auto-generated DTOs for any model <ModelName> always end with <ModelName>Response, Create<ModelName>Request, or Update<ModelName>Request — raw model entities can never be returned directly from REST endpoints. When an endpoint returns a custom DTO, Zenith supports two approaches:

dto_returns.zen 
dto OrderSummaryResponse {
    orderNumber: String
    totalAmount: Decimal
    status: OrderStatus
    processedBy: String?
}

// Approach A: Explicit return construction inside action
post "/{id}/pay" -> OrderSummaryResponse {
    action: {
        status = OrderStatus.PAID
        return OrderSummaryResponse {
            orderNumber = entity.orderNumber,
            totalAmount = entity.totalAmount,
            status = entity.status,
            processedBy = currentUser.email
        }
    }
}

// Approach B: Automatic field mapping (zero boilerplate)
get "/{id}/summary" -> OrderSummaryResponse {
    // Coincident fields (orderNumber, totalAmount, status) map automatically
}

10. Declarative Database Seeding

Populate development and staging environments instantly using seed Model { ... }. Zenith generates a Spring Boot ApplicationRunner (active in non-prod profiles) with password hashing and relational cross-referencing via seed Model[index].

seeds.zen 
seed UserEntity [
    {
        email: "admin@nexus.dev",
        password: "AdminSecret2026!",       // Automatically BCrypt hashed
        fullName: "Platform Admin",
        role: ADMIN
    },
    {
        email: "customer@example.com",
        password: "Pass1234!",
        fullName: "John Doe",
        role: CUSTOMER
    }
]

seed Order [
    {
        orderNumber: "ORD-2026-001",
        totalAmount: 149.99,
        status: PENDING,
        customer: seed UserEntity[1]          // Cross-references 2nd UserEntity record
    }
]

11. Modular File Imports

Decompose large schemas into clean, focused .zen modules using import "./filename.zen". Zenith resolves diamond imports, prevents circular dependencies, and compiles the entire workspace into a single unified AST.

schema.zen (Root Entrypoint) 
import "./config.zen"
import "./auth.zen"
import "./catalog.zen"
import "./orders.zen"
import "./jobs.zen"
import "./seeds.zen"

12. Object Storage (S3 / MinIO)

Decorate fields with @file or @image to automatically generate multipart upload controllers and streaming download endpoints. Switch between MinIO and AWS S3 in config without altering code.

storage_example.zen 
model Product {
    id: Long @id @auto
    title: String

    // Media image upload with MIME type and size checks
    coverImage: String? @image(maxSize = "5MB", types = ["image/png", "image/jpeg"], path = "products/")

    // Datasheet PDF upload
    specSheet: String? @file(maxSize = "10MB", path = "specs/")
}

// Generated Endpoints:
// POST /api/v1/products/{id}/coverImage (multipart/form-data)
// GET  /api/v1/products/{id}/coverImage (download stream)

13. Scheduled Workers (Cron)

Declare background batch jobs and cleanup routines using job Name { cron: "...", action: { ... } }. Zenith generates a Spring @Scheduled component with ThreadPoolTaskScheduler and bulk stream pipelines.

jobs.zen 
job ArchiveOldOrders {
    cron: "0 0 2 * * ?"               // Executes 2:00 AM daily
    description: "Nightly maintenance archiving delivered orders older than 60 days"
    action: {
        update Order {
            where: status == OrderStatus.DELIVERED and updatedAt < daysAgo(60)
            status = OrderStatus.CANCELLED
        }
    }
}

14. Full-Stack TypeScript Client SDK

Zenith generates a zero-dependency TypeScript client SDK in sdk/typescript/ containing strongly-typed models, fetch API clients with JWT bearer injection, and React Query caching hooks.

React Component Example 
import React from 'react';
import { createClient } from './sdk/typescript/src/client';
import { useOrderList } from './sdk/typescript/src/react-query';

const api = createClient({
  baseUrl: 'http://localhost:8080',
  getToken: () => localStorage.getItem('jwt_token')
});

export function OrdersDashboard() {
  const { data, isLoading } = useOrderList(api, { page: 0, size: 10, sort: 'createdAt,desc' });

  if (isLoading) return <div>Loading orders...</div>;

  return (
    <ul>
      {data?.content.map(order => (
        <li key={order.id}>{order.orderNumber} - ${order.totalAmount} ({order.status})</li>
      ))}
    </ul>
  );
}

15. Automated Test Generation

Zenith synthesizes complete JUnit 5, Spring Boot Test, and MockMvc test suites under src/test/. Tests run against an isolated in-memory H2 profile (application.yml) so mvn test passes anywhere without requiring external databases or Docker.

Test File Framework Assertion Coverage
application.yml Spring Test Profile In-memory H2 (create-drop), disabled Flyway, mock secrets.
*ApplicationTests.java @SpringBootTest Verifies application context startup and bean wiring.
AuthControllerTest.java MockMvc Asserts /auth/login and /auth/register validation errors and bad credentials.
*ControllerTest.java MockMvc + @WithMockUser Asserts unauthenticated (401), forbidden roles (403), validation (400), not found (404), and happy paths.
*RepositoryTest.java @DataJpaTest Verifies JPA entity mappings, constraints, foreign keys, and queries under H2.
Terminal 
mvn test
